Method, caveats and raw data

Collection. Every night at midnight a worker queries public job boards through JobSpy and stores what it finds in SQLite. Every run issues the same set of queries — sampling a rotating subset would be cheaper, but then the count would move with the rotation rather than with the market. Every run is also written to S3 as gzipped JSON.

What "active" means. A listing is counted as active on every day between the first and last run that saw it: the window opens at the posting date (or the first day we saw it, whichever is earlier) and closes on the last day we saw it, capped at ACTIVE_WINDOW_DAYS. There is deliberately no grace period past the last sighting — that would make the most recent days slope downward on their own, whatever the market did.

The shaded region. Days before our first scrape are reconstructed from posting dates. We can only reconstruct listings that were still live when we first looked, so that stretch understates the past and slopes upward artificially. It is shown for context and is never used to fit the model.

The forecast. For the first month of collected data the projection is an ordinary least-squares line. After that it switches to a non-seasonal ARIMA(p, d, q), fitted by Hannan–Rissanen and selected by AICc, on a trailing window of recent days. It is fitted in log space, so the trend is multiplicative and the forecast cannot go negative, and the trend is damped so it flattens instead of running off the chart. The band is a 95% prediction interval.

This is an extrapolation, not a prediction. It assumes the recent pattern simply continues. It knows nothing about hiring cycles, funding, policy or layoffs, and the interval only covers the model's own noise — not the chance the model is wrong.
